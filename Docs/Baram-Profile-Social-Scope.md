# 상태창·교환·그룹 확장 요청

사용자 요청: 2026-09-14. UI뿐 아니라 실제 교환·그룹 기능까지 모두 포함한다.

## 확정 요구

- 앞으로 이미지·아이콘·글꼴·사운드는 제공된 원본 클라이언트 리소스만 사용한다. 외부 패키지 시각 자산이나 생성 이미지는 사용하지 않는다.
- 상태창의 교환/그룹 버튼은 원본 ON/OFF 이미지와 허용 설정을 연결한다.
- 그룹 아래 원본 클라이언트 아이콘을 추가한다. 해당 아이콘으로 능력치 목록을 확인한다.
- 기본 목록: 무기, 갑옷, 방패, 왼손, 오른손, 보조, 보조. 실제 장착 데이터만 표시한다.
- 능력치 목록: 전투력, 공격력, 방어력, 명중, 회피, 치명타. 계산 연결 전 값은 0이다.
- 목록의 위/아래 화살표와 원본 크기 비트맵 글꼴을 유지한다.
- 실제 양방향 교환 요청·승인·제시·확인·취소와 그룹 초대·가입·탈퇴를 포함한다.
- 교환은 서버 검증, 제시 내용 변경 시 확인 무효화, 수량/소유권/용량 검증, 종료·취소·저장 실패 시 아이템 유실/복제 방지를 검증해야 한다.

## 조사 근거와 미확정 경계

- `Docs/BaramProfile/README.md`, `manifest.json`: 원본 `LOOKBTN.EPF` 0~5 프레임과 상태창·글꼴 출처 확보. 기존 구현은 비활성 버튼 이미지뿐이다.
- `BaramWorld.mlua`: `SetExchangeAllowed`, `FrontUser`, `ItemAction(give/giveall)`은 존재한다. 양쪽 확인을 거치는 교환 시스템으로 취급하지 않는다.
- `BaramWorld.mlua`: `equip` 한 슬롯으로 장비를 관리한다. 일곱 장비 항목과 임의로 연결하거나 미장착 장비를 꾸며 표시하지 않는다.
- `conf/message.txt`: 교환 허용/거부, 거리 제한, 교환창/소지품 용량 초과, 상대 확인, 성공·취소 및 그룹 가입/탈퇴/해체/그룹장 위임 메시지를 확인했다.
- `map.exe` 0x426800/0x426B10/0x426C30/0x4271C0에서 같은 맵의 이름 조회, 양쪽 허가, 그룹장 추가·제외, 12명 제한, 자기 이름으로 탈퇴, 그룹장 자동 승계, 2명 미만 해체를 확인했다. 경험치 분배 함수는 추가 추적 대상이다.
- 공식 inventory-package는 별도 PlayerInventory/PlayerDBManager 기반이다. 기존 저장과 UI를 대체 설치하지 않았다.
- 계획의 기존 M4 그룹/교환 항목을 지금 구현해 달라는 우선순위 변경 요청이다. 현재 M1 작업을 완료로 바꾸지 않는다.

## 상태

### 구현 체크리스트

- 🟡 상태창 기본 장비 7행·원본 세 번째 아이콘 능력치 전환·스크롤. 현재 저장 구조에 있는 무기만 실제 이름 연결, 미장착 나머지는 빈 항목.
- 🟡 원본 LOOKBTN 0/1/2 활성 이미지 그룹 보관함 등록 및 실제 로드 성공. 자신의 교환·그룹 허용 설정을 서버에서 변경하고 아이콘 갱신.
- 🟡 원본 양방향 교환창·제시/금전/양쪽 확인/취소·저장 복구 연결. `BaramTradeStore`·기존 저장 연결 구현, 분리된 전송 계산/저장 장애 8종/실제 저장 CAS 검사 통과. 실제 두 사용자 검증은 미완료.
- 🟡 실제 그룹 구성·가입·탈퇴·그룹장 제외·자동 승계·해체 연결. G 이름 입력과 다른 캐릭터의 그룹 아이콘 사용. 실제 두 사용자 검증 필요.
- ⬜ 원본 그룹 경험치 분배와 그룹 목록 화면 연결.
- ⬜ 전체 빌드·런타임·실제 두 사용자 교환 및 그룹 검증.

상세 규칙과 주소 근거는 `BaramProfile/Original-Social-Evidence.md`에 기록했다. 교환 12칸, 시작 거리 가로/세로 각각 4칸, 시작 요청 3000ms, 양쪽 확인 및 그룹 12슬롯 구조를 확인했다. 교환창은 원본 NPAL8 팔레트로 추출하여 그룹 보관함에 등록했다. 20:01 이후 실제 Maker에서 원본 창 3종과 LOOKBTN 3종 로드 성공, 메인/추가/수량 창 스크린샷을 확인했다. ADD/선택/수량/Backspace는 UI 이벤트 주입 검사이며 실제 두 사람 거래 검증과 다르다. 검사 전용 미리보기는 닫았다.

사용자는 확인되지 않은 규칙을 임의로 정하는 방향을 거절하고 원본을 더 확인해 구현하라고 요청했다. 상태창과 그룹의 런타임 코드/UI를 수정했다. Maker 로그에서 능력치 전환 후 `stats=true critical=true`, 장비 전환 후 `equipment=true extra=true`를 확인했다. 그룹 및 실제 두 사용자 간 검증은 별도 필수다.
