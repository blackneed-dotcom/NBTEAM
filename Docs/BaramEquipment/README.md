# item2 장비 연결 (2026-09-16)

## 사용자 지정 제외
- 사망 처리 deathType: 데이터만 보존. 사망 동작에 연결하지 않음.
- 수련봉(55), 수련검(56): 착용 이미지 연결 제외. 다른 그림으로 대체하지 않음.

## 적용
- 동일 슬롯·아이템 두 번째 우클릭: 파란 정보창 닫기. 누른 상태의 중복 UI/키보드 이벤트는 한 번만 처리.
- item2_db.txt 154개 무기 중 152개 착용 외형. 118개 착용번호/염색 조합, 3,040프레임 참조, 중복 제외 1,992개 PNG.
- char.dat SWORD/SPEAR TBL의 ID→팔레트/시작프레임을 사용. 96×96, 발 기준 (48,72), 원본 색상 인덱스 염색 유지.
- 아이콘 imageId와 착용 equipImageId를 분리. 기존 아이템 17 고정 목도 코드 제거.
- 타입/최대 개수/내구도/가격, 힘·민첩·지력·성별·레벨·직업·승급 조건, 버리기/교환 여부 연결.
- 공격 피해 = 기존 기본 피해(1~2) + DB 공격력 + 도감 공격력. 현재 DurabilityLossEnabled=false로 공격/내구형 사용 아이템의 내구도 감소 중지.
- 삼지창(25)의 공격력은 원본에 비어 있음. 추가 공격력 0, 원본을 임의 수정하지 않음.
- 기존 착용도 로그인/직업 변경/상태 갱신 때 조건 재확인.
- 수리 가능 여부와 비용 적용. 현재 수리비 = ceil(부족 내구도 × repairCost). 비용 부족·수리 불가·완전 수리 상태 거부.
- 주막(8) 메뉴에 장비 수리/장비 명명 추가. 아홉 번째 메뉴는 아래 화살표로 이동.
- 명명비 차감, 1~12자 한글 입력. 아이템 ID/외형 유지, 인벤토리·캐릭터 정보·전달/교환/드롭에 이름 보존.
- 기존 보관·되찾기 비용/내구도 조건 유지, item2 데이터로 계산.
- 착용/해제/공격 스크립트는 기존 인터프리터에 연결. 현재 154개 데이터의 세 스크립트 열은 모두 '-'이므로 추가 스크립트 실행 없음.
- 툴팁·설명·조건·내구도·가격·수리/보관/명명비 표시.

## 재생성
Maker 정지 상태에서 export.cjs → upload.cjs → bind.cjs → Maker Refresh.
원본/등록 매핑은 inventory.json, uploaded.json에 보관. upload-status.json의 성공 완료 확인 후 바인딩.

## 검증
- 서버: 154개 장비의 장착/레벨/직업/내구도/공격력/수리 조건, 명명과 복사, NPC 보관·되찾기 비용 테스트 통과.
- 클라이언트: 목록/아이콘 모드 정보창 토글, 중복 누름, 닫힌 뒤 Refresh 유지 테스트 통과.
- 118개 외형·염색 조합의 전면 스프라이트 엔진 로드 성공.
- 실제 HeldWeapon 렌더러: 목도/장창/적호박별검/원혼마령봉 RUID 적용 확인.
- 주막 아홉 번째 명명 메뉴와 한글 입력창 진입 확인.
- 입력 검증은 Maker Lua로 실제 처리 메서드를 호출. 물리 마우스 클릭 자동화는 지원되지 않아 별도 실마우스 테스트로 주장하지 않음.
- 기존 원본 Ba*.map 바이너리의 Maker JSON 파싱 메시지는 이 변경 범위 밖. 새/변경 스크립트 빌드 오류 없음.
