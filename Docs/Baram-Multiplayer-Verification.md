## 1차 Maker 검사

- CoreVersion 26.7.0.0, 기존 sector01 최대 16명 설정 확인. 공개/게시 설정은 변경하지 않았다.
- 새 빌드 오류 0. 기존 채팅 gsub 다중 반환 관련 경고 2개가 남는다.
- `[MultiplayerVerify] duplicate claim / full bag / wrong cell / expiry / metadata PASS`: 분리된 인벤토리 2개로 동일 드롭 중복 요청 거절, 가방 부족 복원, 다른 좌표/만료 거절, 수량·내구도 보존.
- `[MultiplayerVerify] stale cleanup / unsaved data / saving / loading guards PASS`: 별도 검사 레코드로 오래된 정리 요청/미저장/저장 중/로드 중 보존 검사. 종료 후 검사 레코드를 제거했다.
- `[MultiplayerVerify] superseded/cancelled entry tickets PASS`: 로드 티켓이 교체/취소되면 이전 티켓을 거절한다.
- 실제 저장 캐릭터 1번 슬롯의 입장 → 채팅(수신자 1명) → 타이틀 복귀 → 재입장. Active 동기화, 표시/터치 정리, 표시 재생성 로그 확인. 아이템·금전·외형의 테스트 값 덮어쓰기 없음.
- 위 결과는 2계정 접속 테스트가 아니다. 이전 걸음 모션 보완 코드는 유지했다.
- 최종 수정 후 다시 빌드 오류 0, 입장 활성 상태와 표시 생성 `final entry active/display PASS`를 확인했다.

## 실제 두 계정에서 확인할 절차

1. 같은 월드 인스턴스에 A/B로 들어가 서로 보이는지 확인한다. 다른 맵으로 이동했다 돌아와도 표시가 중복되거나 남지 않아야 한다.
2. 서로 다른 방향으로 걷고 방향을 꺾는다. 상대 외형/위치/공격 동작이 보이는지, 동일 셀로 이동할 때 서버가 겹침을 거절하는지 확인한다.
3. 같은 맵에서 채팅하고, 한 명이 다른 맵 또는 타이틀로 가면 해당 채팅을 받지 않는지 확인한다.
4. 같은 몬스터를 공격해 처치/드롭이 한 번만 발생하는지 확인한다. 같은 드롭을 연속해서 주워도 총 수량이 늘어나지 않아야 한다.
5. 그룹 가입·탈퇴와 교환 제시·양쪽 확인·취소를 실행한다. 한 명의 접속 종료로 교환창/그룹이 올바르게 정리되는지 확인한다.
6. 두 계정을 재접속해 각자 외형·위치·소지품·금전이 섞이지 않는지 확인한다.

## 공개 전 남은 경계

실제 두 계정 네트워크 검사와 그룹의 남은 기능은 미완료다. 직접 전달(give) 및 지면 드롭은 메모리에서 중복 처리를 막지만 서버 프로세스 강제 종료까지 원자적으로 보존하는 방식은 아니다. 기존 WorldConfig의 네이티브 권한 검사 옵션은 false이며, 이를 켤 때 기존 클라이언트 네이티브 호출의 호환성 검토가 필요하다. 이번 단일 클라이언트 검사를 보안/장애 내성 전체 완료로 취급하지 않는다.

## 범위와 한계

이동은 기존 서버 셀 검증, 외형은 플레이어별 동기화 속성, 몬스터/드롭은 서버 엔티티를 유지한다. 서버와 다른 클라이언트 사이의 실제 화면 일치, 동시 사냥/교환, 재접속은 두 계정이 필요하다. 단일 Maker 클라이언트의 모의 검사를 2인 테스트 통과로 기록하지 않는다.
