# 인벤토리 클릭 수정 — 2026-09-16

## 실제 무반응 원인

BaramInventory/Frame은 640×480 UI를 UIScale=(3, 2.25, 1)로 확대한다. Maker 런타임의 ScreenToLocalUIPosition은 피벗을 기준으로 한 차이를 반환하지만 이 상위 배율을 제거하지 않는다. 기존 InventoryRowAtPosition은 그 값을 확대 전 RectSize=(130,13)과 비교했다.

첫 행 피벗은 (1392,949.5), 보이는 중앙은 (1587,934.875)였다. 중앙의 반환 좌표 (195,-14.625)를 (130,13) 범위와 비교해 hit=0으로 거부했다. UI 이벤트도 같은 재검사를 거쳐 무반응이었다. 이전 검증은 피벗 근처만 검사해 이를 놓쳤다.

## 수정

BaramInput.InventoryRowAtPosition에서 행부터 인벤토리 루트까지 UIScale을 누적하고, 반환 좌표를 X/Y 배율로 나눈 뒤 RectSize와 비교한다. 고정 숫자를 코드에 넣지 않아 부모 배율 변경에도 적용된다. 현재 회전 없는 인벤토리 계층을 대상으로 한다.

기존 클릭 상태 처리(동일 항목의 좌클릭 두 번, 우클릭 설명, 중복 이벤트 방지, 창 전환·드래그 취소)는 유지한다.

## 검증 결과

- 빌드 오류 및 수정 메서드 진단 0건, git diff --check 통과.
- 목록·아이콘 각각 현재 세 항목의 가로·세로 5%/50%/95% 위치: 총 54개 모두 해당 행 판정.
- 기존 실패 좌표 (1587,934.875)에서 우클릭 UI 이벤트: 설명 표시 확인.
- 같은 좌표의 좌클릭 UI 이벤트 두 번: 서버 장착 슬롯 1 확인.
- 테스트 장착 상태 복원 확인.

검증은 Maker 런타임 좌표 검사 및 행 엔티티의 UITouchDown/Up 이벤트 전달로 수행했다. Windows Computer Use의 native pipe 연결 실패로 OS 마우스 자동 클릭은 수행하지 못했다. 소비 아이템 수량은 변경하지 않았다.
