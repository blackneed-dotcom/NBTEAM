# 바람 접속 화면 구현 기록

범위: 원본 화면 리소스를 이용한 로딩 → 타이틀 → 처음하기 → 생성 완료 → 이어하기 → BaramMinimalTest 진입. 닉네임은 후속 작업.

## 구현
- `ui/BaramEntry.ui`: 원본 640×480 비율 유지, 4:3 화면과 검정 여백. 화면 해상도 1920×1080 기준 배율 2.25.
- `BaramEntryFlow.mlua`: 처음하기/이어하기, 취소, 성별/국가/수호신 선택 및 표시, 서버 검증, MSW 계정별 저장 및 불러오기.
- 저장소: UserDataStorage(ProfileCode), 키 BaramCharacterV1, 값 2:gender:nation:totem:hair. 이전 3항목 형식도 읽음. 기존 캐릭터는 국가/수호신을 유지하며 외형 수정 가능. 이름/비밀번호를 수집하지 않음.
- BaramChatRelay 입력 가드에 접속 화면 상태를 연결. 게임 입장 전 이동/채팅/HUD 단축키 차단.
- 타이틀 TITLE.EPF + NPAL2.PAL, 생성 DLGNEW02.EPF + NPAL3.PAL, 접속 DLGLOGIN.EPF + NPAL8.PAL. DLPalette RGB 색상으로 추출. 팔레트 매핑은 시각 검사에 근거하며 원본 로더 코드와 대조하지 못함.
- 원본 DAT/EXE/DLL 변경 없음. extract.cjs와 build.cjs로 자료 추출 및 UI 재작성 가능.

## 검증
- Maker: 로딩 후 title 전환, 생성 전 이어하기 거절, 선택 변경 및 취소.
- 실제 Maker mouse_input: 처음하기 버튼 → create, OK 버튼 → 서버 저장 성공.
- 독립된 테스트 저장 키로 1:1:3 저장, 다시 읽기 code=0, 서버 캐시를 비운 뒤 불러오기 성공.
- 이어하기 → login → enter → 테스트 맵 입력 허용 확인.
- 테스트 키 BaramEntryVerify_20260914_0601만 삭제. 실제 BaramCharacterV1 키에 테스트 캐릭터를 저장하지 않음.

## 아직 원본과 다른 부분
- 로딩 화면은 원본 전용 리소스를 확인하지 못해 실제 리소스/계정 로드를 알리는 텍스트 화면으로 구현.
- 외형은 원본 몸 2종·머리 10종을 생성 화면과 게임에서 공유한다. 좌우는 머리 선택, 회전 버튼은 방향 확인. 원본의 전체 선택 목록·성별별 제한은 미확인. 상세 분석은 ../BaramAppearance/README.md 참조.
- 국가/수호신은 선택 정보만 저장. 해당 수치/능력 효과는 이번 범위 밖.
- 닉네임 보류; 원본 비밀번호 인증 대신 MSW 계정 사용.
- 타이틀의 암호변경/배경이야기/만든사람들/종료는 배경 이미지에 포함되어 있지만 아직 동작을 연결하지 않음.
- 픽셀 단위 원본 일치, 원본 로딩 연출/시간, 실제 재접속 전체 흐름은 추가 검증 대상.
