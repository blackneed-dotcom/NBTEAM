# 제공된 실행파일의 교환·그룹 분석

2026-09-14. 실행파일은 **실행하거나 수정하지 않고** PE 섹션과 x86 명령을 읽었다. 아래는 제공된 파일 버전의 근거이며, 공식 서비스의 다른 버전까지 동일하다는 뜻은 아니다. MSW 기능 구현/검증 완료 문서가 아니다.

## 서버 실행파일에서 확인한 규칙

주소는 image base 0x400000 기준 VA이다. map.exe에는 보호용 추가 섹션이 있지만 아래 관련 함수의 x86 명령은 읽을 수 있다.

- bint.dat/DLGEXC1.EPF frame 0: 506×322. 양쪽 목록과 OK / ADD / CANCEL 버튼이 원본 이미지에 들어 있다.
- DLGEXC2.EPF frame 0: 287×277. 단일 목록과 OK / CANCEL 버튼.
- DLGEXC3.EPF frame 0: 287×277. 원본 보조 창 배경. 용도와 문자/입력 오버레이는 아직 추적 중이다.
- winbaram.exe 0x42BA81~0x42BA9F 및 0x42C02B~0x42C059: 교환 메인창 506×322 구성과 상태 초기화.
- 버튼 사각형 생성 호출:
  - OK: 0x42BAE3~0x42BAF5 → (42,272)-(114,288).
  - ADD: 0x42BB2E~0x42BB46 → (217,272)-(289,288).
  - CANCEL: 0x42BB7F~0x42BB97 → (392,272)-(464,288).
- 왼쪽 목록 사각형: 0x42BC8A~0x42BC9F → (36,89)-(251,232).
- 0x42C0A0의 버튼 처리: 두 번째 분기에서 0x42D180 보조창 생성, 첫/세 번째 분기에서 0x4A 패킷 작성. 서버 수신 0x44EE.. 디스패치와 연계 확인 필요.
- 팔레트 추가 확인: 메인 생성자의 문자열 VA 0x552340은 `NPAL8.PAL`이다. 추가/수량 창도 NPAL8을 참조한다. 초기 NPAL6 추출본은 사용하지 않고 NPAL8로 재추출했다. 인덱스 투명도를 유지했고 덧칠하지 않았다. 20:01 이후 Maker 스크린샷으로 교환 메인/추가/수량 창을 확인했다.

## 구현 및 검증 기록 (20:03 갱신)

- `item_db.txt` 헤더의 `버리기가능(=교환여부)`로 dropAllowed 대응을 확인했다.
- 추가창 0x42D180: 287×277, 목록 (36,61)-(251,205), 확인 (69,225)-(141,241), 취소 (146,225)-(218,241). 선택 목록 순회는 0x42D410.
- 수량창 0x42D850/0x42DB10: 입력 (52,129)-(234,141), `%u` 해석 후 255 제한. 금전 입력은 동일 원본 배경을 재사용하지만 원본 금전 입력 경로의 완전 동일성은 아직 확인하지 않았다.
- 원본은 제시 시 임시 보관/취소 반환 방식이다. MSW 구현은 서버 예약 + 최종 검증 후 저장 결정 방식이며, UI가 보낸 인벤토리/금전 잔액을 신뢰하지 않는다. 저장 중에는 변경을 잠그고 보류한 전투 처리를 잠금 해제 시 재개한다.
- 원본처럼 이미 확인한 사용자의 재확인/제시 변경은 취소한다. 추가로 양쪽 확인 revision이 같아야 완료하도록 안전 검증했다. 이는 원본 바이너리의 revision 프로토콜을 복제했다는 뜻이 아니다.
- 캐릭터 저장값에 pending 결과를 함께 저장하고, 별도 저장소의 CAS 결정(committed/aborted)으로 두 사용자 복구를 일치시킨다. 저장 결과가 불명확하면 거래 잠금을 유지한다. 두 사용자 저장을 단일 플랫폼 트랜잭션으로 처리한다고 주장하지 않는다.
- Maker 분리 테이블 검사: 수량·내구도·금전 보존·입력 불변·overflow 거절 통과. 저장 장애 모의 8종(준비 실패/적용 후 timeout/결정 timeout/복구 재시도) 통과.
- 실제 API 검사: `BaramTradeVerificationV1`의 새 GUID 검사 키에서 CAS 성공/오래된 값 거절/결과 유지 통과. 캐릭터 저장소는 변경하지 않았다.
- UI 검사는 표시 전용 세션과 UITouchDownEvent/키 메서드 주입으로 수행했다. 실제 두 사용자 RPC·접속 종료 검증은 남아 있다. 그룹 경험치/목록도 미완료다.

## 다음 필수 작업

추가 조사: `map.exe` 0x40853C 및 0x444A48의 처치 경로에서 그룹이 있으면 0x426F80을 호출하고, 없으면 0x429A90으로 직접 경험치를 지급한다. 0x426F80은 12슬롯 중 동일 맵(+0x2E4) 구성원의 레벨(+0x3CF)을 합산한 다음 `max(1, trunc(기본 경험치 × 해당 레벨 / 동일 맵 레벨 합))`을 각각 0x429A90으로 전달한다. 별도의 거리 검사는 이 함수에 없다. +0x3CF의 레벨 의미는 0x429B5D의 평민 5레벨 및 0x429B95의 99레벨 비교로 교차 확인했다. 이는 분배 함수 조사 결과이며, 공통 지급 함수의 보정/상한/유령 상태 제한까지 구현 완료했다는 뜻이 아니다.

1. 클라이언트 교환창의 팔레트·투명색, 오른쪽 목록·금전·추가/수량 입력과 상태별 버튼 추적.
2. 그룹 가입/탈퇴/리더 위임과 경험치 분배 경로, 교환 취소 반환·확인 이후 제시 동작의 원본 규칙 확인.
3. 기존 인벤토리/저장과 양방향 교환의 원자성·중복 방지·접속 종료 복구 설계 및 구현.
4. 상태창 원본 ON/OFF, 기본 장비 7행, 능력치 아이콘 전환과 원본 교환창 구현.
5. Maker 빌드·실행·입력 검증 및 실제 두 사용자 교환/그룹 검증. 조사만으로 완료 표시하지 않는다.
