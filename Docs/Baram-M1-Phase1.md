## 다음 작업의 구체적 기준

1. **예외 행:** inventory.json의 rejectedNumericRows 원문 확인. 데이터가 빠져도 조용히 정상으로 취급하지 않고 수정 어댑터 또는 제외 사유를 남긴다. 원본 파일은 수정하지 않는다.
2. **맵:** CMAP의 세 uint16 필드와 TILE.DAT 리소스·충돌 표 의미를 기존 Ba000010 추출 결과와 비교. 부여성 출입구·실내 벽·사냥터 가장자리에서 통과 가능 여부를 검사한다. 단순 배경 그림 표시를 충돌 구현으로 취급하지 않는다.
3. **서비스:** pursuit_db와 NPC 스크립트, shop_db의 연결을 사용. 아이템 구매/판매 가격·사용 함수까지 연결하며 이벤트 NPC는 첫 목표 대상에서 제외 사유를 기록한다.
4. **게임 규칙:** script_essential·function·item의 시작 장비/소비/드롭 함수를 추적. 원본 데이터와 실제 적용값을 분리해 기록한다. 사슴 176/300은 같은 사냥터 원본 배치에 있으나 M1의 두 몬스터 검증이 끝날 때까지 활성화하지 않는다.

## 검증 경계

현재 결과는 원본 분석·변환 준비 단계다. 신규 맵·대화·전투는 아직 런타임에 연결하지 않았다. 등록 후에는 Maker refresh→build logs→play→runtime logs→입력·화면 검사까지 통과해야 해당 구현을 ✅로 바꾼다.
